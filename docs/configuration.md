# 配置与归档规则

## 本地配置

开发入口的 `dev.example.json` 是可用的离线默认配置。网关 `.env.example` 只列出配置入口；真实账号、应用 ID、聊天 ID、凭据目录、模型与资料路径应填写在本机 `.env`、`*.local.*` 或 `.dev-runtime/`，不提交 Git。

连接真实服务需要自行安装并授权飞书官方 CLI、所选 AI 客户端和所需转换工具。当前主线包含 Codex app-server 适配器，另有实验性转换/模型适配代码；仓库名称中的历史目录不表示强制使用某一模型。实际模型由本地运行配置决定，不能从文件名推断。

真实服务启动涉及 `daily_policy.py`、冻结部署清单、凭据代理与 `install_daily_launcher.py`，需要按自己环境核对；这里不提供可以直接启动真实账号的预先批准文件。`--help` 可查看各入口参数。业务模型累计保存于本地账本，重启或更新代码不重置计数。

## 整理规则示例

`examples/reading-rules/` 提供三个可公开使用的通用规则，分别对应：

| 引用角色 | 示例文件 | 作用 |
| --- | --- | --- |
| `archive_rules` | `archive-rules.md` | 目录、来源与归档边界 |
| `organize_prompt` | `organize-prompt.md` | 导读、卡片与主题整理 |
| `nlp_skill` | `evidence-rules.md` | 证据、引用与独立复核 |

`ReadingProfile` 要求这些文件的绝对路径及 SHA-256 与部署清单一致，整理脚本来自审阅过的当前工作区。修改规则后必须重新核对绑定。个人偏好可以在本地规则副本中维护，不能把私人库的路径或材料复制到公开示例。

目标固定为运行内容目录的 `reading-library` 子目录，不会继承个人规则中可能提到的正式库路径。输出目录为 `10_Reading_读书摘录`、`20_Cards_知识卡片`、`30_Topics_主题索引`、`40_Projects_专项引用`、`50_Daily_Briefs_知识简报`。

## 确认与范围

来源登记、正文授权、预览后确认入库和关联确认只约束本服务接管的材料。项目外、非飞书来源的本地手动归档，应使用其自身流程；不能因为缺少本服务登记而阻止已授权的本地操作。

开发库应与个人正式库隔离。正式库导入、已有资料合并、磁盘迁移和远端备份分别安排，不由服务启动或代码提交隐含触发。
