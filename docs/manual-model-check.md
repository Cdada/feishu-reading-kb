# 读书简报模型变更：手动检查

这是知识库 V2 保留的管理功能，由 Codex 在用户明确提出检查时执行。它不注册定时任务，也不新增飞书机器人命令。

## 如何调用

用户可说“检查读书简报的模型变更”“检查知识库 V2 的简报模型是否需要调整”。仅讨论模型、收到定时心跳或发现新型号，不自动执行本流程。停用原有模型提醒定时任务，不影响阅读简报投送或独立的离线回归任务。

## 检查步骤

1. 读取本机绑定说明 `.dev-runtime/kb-v21/manual-model-check.local.md`，确认目标简报项目、上次已验收基线和已知问题。该文件只留本地；缺少绑定时先明确目标，不猜测或扩大扫描范围。
2. 只读核对简报配置与编辑脚本中的模型、Provider（模型服务商）、推理/思考设置、输出上限；只读取最近运行和必要送达台账中的模型与状态字段，不读取或输出阅读正文。
3. 安全解析本机 Codex 配置、指定子 Agent 配置和相关模型目录条目，只提取与本次检查有关的字段，不输出密钥、凭据或无关配置。不导入或执行简报编辑脚本来检查参数。
4. 核对 DeepSeek、OpenAI 官方发布、模型别名及弃用说明。即使别名未变，也检查它指向的模型或能力是否发生重大变化；记录官方信息日期与来源。官方发布、账号可用性和本机目录记录分开判断，独立 API 模型不以 Codex 目录是否收录为准。
5. 将当前配置、最近实际运行与官方变化比较，说明对简报质量、兼容性或运行的影响。模型移除、弃用、明确不支持或有显著影响的后继型号时给出选项，由用户决定是否更换。

## 执行边界

- 手动检查本身不修改模型、Provider、凭据、Skill、简报日程或其他定时任务，不发送试运行请求、不发起付费验收，不自动回退或重装。
- 简报独立 API、桌面主模型和原生子 Agent 分别核验；某条通道成功不代表其他通道可用。桌面主模型变化只提示相关兼容性核验，不因此更换简报模型。
- 只有官方文档或运行时证据明确表明跨 Provider 派发限制改变时，才建议重新验收原生子 Agent；仍须用户另行批准实际验收。
- 既有故障和已报告但未决定事项，没有新证据时不反复作为新问题提醒。配置或检查失败要标为无法确认，不能声称没有变化。
- 管理结果只回复当前聊天，不写进阅读简报或熊掌记阅读正文，不向其他人发消息。个人路径、账号、运行台账及检查证据只留本地。

## 结果格式

手动请求应得到简短结果：实际读取的范围、是否发现有意义变化、影响及是否需要用户决定。没有变化时明确说明“本次未发现需要调整的变化”；未能核对的部分单列。保留本地历史，不覆盖旧验收结论，不重置工时或模型累计记录。
