# 归档主卡：阶段二

启用 `archive_cards: {reference: archive-main-v1, enabled: true}` 后，仅新登记的任务使用主卡。历史队列、已发送的确认卡和既有发布流程继续有效。

主卡显示收件排队、运行条件核对、原件保存、页面转换、导读生成与核验、预览发送和确认。导读 PDF 仍独立发送供阅读。成功页数只代表页面转换，不能代表入库完成。更新复用现有报告循环，普通状态至少合并 15 秒；不承诺每页即时刷新，不改变主调度线程。

普通页面进度按约 10% 合并更新，显示的数字仍是实际成功页数。新主卡最多允许 64 次更新尝试，为确认、复核、暂停和完成状态保留空间；原卡片仍保持 20 次。全局每日、每分钟请求额度及逐次记账保持原样。

每个任务保留一张物理卡片。确认按钮使用原有不可变的导读版本标识，绑定已经发送并回读核验的 PDF；主卡展示与业务决定分别保存。旧按钮、其他材料的按钮、重复点击不得改变当前决定。原 PDF 的文字回复继续有效；主卡文字回复不替代版本明确的 PDF 回复。

重启复用本地绑定。发送或更新结果不明时，先核对原回执和实际消息，不能重新创建卡片或重新运行模型。更新失败只影响显示，必要时发送一次简短通知。缺图说明、需要阅读的文件和确认后的既有整理通知暂时保留；后半段状态统一属于阶段三。

验证使用合成材料与模拟平台回执，覆盖收件到确认和既有发布、重复点击、旧按钮、重新启动、多任务隔离、成功页计数、发送/更新未知结果，以及 CLI 原件和导读权限边界。没有执行私人知识库批量评测，也没有新增业务模型调用。真实飞书展示与移动端操作需要在批准的验收窗口核验。

回退时使用已验证的旧代码和原账本，禁止恢复旧数据库覆盖新决定。已经标记使用主卡的任务应先完成或保留当前版本处理；切回不认识主卡的旧版本之前，需要人工检查这些任务，不能假定旧版回调支持新按钮。
