# 归档检查分级与用量汇总：阶段四

飞书额度沿用原规则：本机原子预留、滚动 24 小时总量、分钟限流和确认操作保留量。原账本不重置，失败和结果不明的预留也计入。代码原本没有远端额度查询，本阶段不增加这种查询，也不增加逐步审批。各来源请求仍共享总限额。

新增本地归属表只记录新请求与材料的关系，复用原账本，不复制回执或正文。资料处理步骤、主卡更新和按钮回读可以明确归属；群身份检查、分页扫描、问答及未能明确归属的请求单列为共享或历史用量。历史记录不倒推分摊。每份计数是可归属部分，不能当成全部成本或平台实际账单。

完成、受阻或暂停后更新队列中的一条用量摘要，随后产生的主卡请求也会在下一轮汇总。现有启动器 status --json 的 summary.http_usage 展示滚动用量、共享用量和材料明细。平常不新增飞书消息；本地状态摘要在达到日限额 90% 时提示。分钟与日限额拦截及平台异常处理继续沿用原规则。

| 工作负载 | 内存条件 |
|---|---|
| 有资源准入的原件流式接收、普通文字导读与整理、导读文件投送 | 不使用 MinerU 的 20%/25% 空闲比例门槛；严重压力、探测失败和磁盘不足仍阻止工作 |
| 不超过 1 MiB 的 MD/TXT 转换 | 采用上述轻量条件；其他格式及更大的文本保留严格条件 |
| MinerU 启动、解析、恢复、分块 | 原严格条件全部保留 |
| 图片导读准备、导读 PDF 渲染、超过 16 MiB 的整理源资料包加载 | 严格条件 |

轻量检查拥有独立状态，不会清除重型工作暂停后的 25% 恢复门槛。模型进程可能尚未释放，因此所有实际重型入口继续检查。磁盘、原件完整性、正文授权和模型订阅条件均保留；确认卡片接收原本没有 MinerU 门槛，继续保持。问答模块自身的资源条件本阶段未调整。

本阶段没有合并既有检查、改变轮询频率、并发数、解析分块或订阅配置；超过 16 MiB 的整理资料包增加加载前严格检查，以覆盖移除全阶段严格门槛后的实际高负载操作。验证使用固定资源样本和合成资料，覆盖警告/严重压力、低磁盘、恢复门槛、保留历史账本、跨线程归属及暂停摘要，不制造真实内存压力，也不重做知识库质量评测。
