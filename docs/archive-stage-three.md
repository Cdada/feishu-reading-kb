# 归档主卡与异常接续：阶段三

新任务的主卡继续覆盖确认后的材料包保存、笔记和适用的卡片与主题整理、独立复核、本机成果校验、发布和完成。复核拒绝时保持未完成，不自动重新调用模型。页面转换、材料包入库和知识整理完成分别显示。

普通整理进度、同任务的 MinerU 生命周期消息和完成提示合并到主卡。导读 PDF、必要的缺图说明、需要回答的补充来源问题，以及独立的资料关联选择仍保留。快速步骤可能在两次报告之间完成，卡片展示当前实际状态，不伪造逐步停留动画。

归档时不增加问答索引重建。卡片明确注明归档流程未核验问答索引，下次提问时按既有规则刷新。卡片更新失败不改变入库状态；首次发出一次简短异常通知，未解决的同一显示问题不反复提醒。已经完成且显示一致的任务不再占用主卡轮询位置。

运行目录中的 `待处理材料与接续说明.local.md` 是唯一汇总文档；不会为每次轮询生成一份报告。每项使用稳定的 `KB-EX-…` 编号，主卡指向对应章节。文档区分等待资源、等待用户补充和需要 Codex 核查，记录真实阶段、用户决定、已有成果标识、模型尝试、成功页、最近状态变化及本机查询位置。到达重试时间不等于资源已经恢复。

机器只更新带明确标记的状态块，保留 Codex 处理备注。恢复后压缩机器摘要，保留编号、当前结论与处理备注。损坏标记、并发编辑、不可写文件等情况会显示更新失败，不覆盖人工内容。该文档是线索，不替代原件、回执、账本和用户确认，也不授予新的模型调用或清理权限。

符合前置条件的受阻 PDF 可查阅已有 `pdf_recover.py` 入口。它要求服务和 MinerU 停止、原件健康、尚无模型预留等条件，并再次核验修复页。其他情况明确标注没有通用自动恢复入口，需要 Codex 逐项核对；本阶段不新增自动修复或泛化重试。

运维入口：现有启动器的本机 `status --json` 返回 `archive_handoff.path` 和接续文档错误状态；无需启动服务即可定位文档。接续说明、回执、私有路径与资料内容均不得上传公开仓库。需要排查时向 Codex 提供处理编号即可。

验证范围为相关程序行为：完整整理、独立复核拒绝、结果不明不重发、卡片显示故障、备注保护、敏感诊断脱敏和已有 PDF 修复路径。使用合成材料和模拟模型，不表示真实知识库回答质量已通过评测。真实飞书界面仍需在明确批准的验收范围内检查。
