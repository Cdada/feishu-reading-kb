# 阶段一：四次自然归档计时与阅读要求

本阶段保留既有归档、逐篇确认、整理及独立复核流程。新增后台计时、导读通读指示和私密主题边界继承。主卡改造、资源准入调整、用量策略及文件清理不在本阶段。

## 启用与查看

在批准的日常运行规则中增加可选字段：

```json
"archive_timing": {"reference": "archive-timing-v1", "sample_limit": 4}
```

规则及其散列应经现有冻结部署流程重新绑定。缺少此字段时不创建计时表，不选择样本；不能用编辑已冻结规则文件的方法临时开关。

启用后，接下来四个新登记任务分别占一个固定名额，包含重复材料、失败或暂停的任务。历史队列不回填，重启、恢复及重复 @ 不增加名额。四个样本仍未结束时继续记录它们，之后的新任务不进入详细采样。

通过以下只读入口查看，服务无需启动：

```sh
python projects/kb-ingestion-workflow/integrations/kb_custody_v21/archive_timing_report.py --root /path/to/private/daily-service
```

加 `--json` 获取结构化结果。不填写真实路径到公开文档或提交中。状态 `not_enabled` 表示尚未建立采样表；`sample_limit_reached` 只表示四个名额已占用，不表示四篇均完成。

输出使用 sample-1 至 sample-4，保留类型、字节数、页数和时间，不复制正文、文件名、消息 ID、原件路径或凭证。内部表以原队列消息 ID 关联，留在既有私有 SQLite 中。报告仍可能反映使用时间，应留本机。

## 记录口径

- 阶段处理耗时使用单调时钟，包含实际调用的转换、生成、核对、预览、整理、复核与发布。
- 内嵌检查记录次数、累计和最长耗时，包括实际运行的权限、资源、来源、消息、订阅、导读覆盖等检查。不额外运行这些检查，不改变频率。
- 网络／模型调用计时包含现有子进程与往返；子进程内部不再逐项测量。共享收件和主线程检查不强行分摊到某篇。
- 页面事件沿用已有解析进度。MinerU 健康检查完成不代表全部模型已加载；首个解析调用仍可能包含延迟加载。
- 用户等待、资源暂停、服务正常停止使用真实阶段或心跳状态；区间可重叠，不可直接相加。
- 阶段就绪至首次执行单列为调度间隔。它可能包含排队、停机与共享检查，不能声称是纯排队时间。进程突然消失的未记录间隔保持未知。
- 中断段不补算耗时，写入 null 和 interrupted。未结束任务不提供总历时；已结束总历时包含等待，不能当成纯处理时间。
- 长时间等候的成功轮询、资源阻塞重试合并次数与实测秒数。合并记录的起止跨度包含间隔，elapsed_seconds 只合计实际执行。
- 每篇最多保留 2,048 个详细段、512 个事件；达到上限明确标记 truncated，不无限增长，业务状态仍继续更新。
- 每段绑定规则、完整源码清单、导读脚本、整理规范散列。source_commit 是运行锚点仓库版本，实际冻结代码以 source_manifest_sha256 识别。跨版本记录不可作为同版对照。
- 问答索引沿用在检索时刷新的行为。本记录明确标记归档期间未观察到索引完成，不额外重建，不以材料已发布推断索引成功。
- 首次反馈指核验后的平台回执时间，无法证明用户设备已经显示。历史回执恢复时可能只能记录本次核验时间。

## 阅读要求及内容边界

实际导读客户端新增：

> 请先通读本次提供的全部正文，再生成导读。整体把握文章的问题、主要论证、结论、适用条件与局限，不得仅依据摘要、开头或少数引文写作。无法完成全部正文处理时，应明确说明限制，不得声称已完成全文阅读。

既有 Skill、C9、引文校验、授权来源、简体中文和不执行源文指令的要求继续生效。Skill 文件版本不变：本次澄清与其现有要求兼容，修改发生在实际客户端指示，脚本散列负责识别版本，避免无关改写导致旧回执重建不一致。

新建私密主题与卡片继承 sensitivity=private、brief_visibility=exclude；向共用主题或卡片追加私密来源后，不得被后续公开来源降级。混合材料主题保留事实／解释／设定边界；虚构与情景推演不作为已验证事实或能力证明。私密来源不进入简报。既有人工修复成果不重做。

## 验证、部署与回退

合成测试覆盖：四样本上限、重启、失败不换样、坏页事务回滚、首次反馈、未知中断、等待聚合、共享主题私密限制，以及完整本地归档仍只调用原有次数的模型和传输桩。离线提示词验证证明接入，不证明模型已通读；真实效果留待下一次正常归档观察。

部署应以当前已验收发布基线加本阶段变更生成冻结版本，不能顺带上线其他未验收功能。部署不等于启动；维持用户当前服务启停选择。私有规则及启动器切换前后核对队列、模型与请求账本，保留旧绑定。

计时表为附加表，旧版 DailyStore 可继续读取原业务表。回退切回原代码和对应原规则绑定，保留现有数据库、确认、材料成果与累计账本；不得恢复旧数据库覆盖新结果。回退期未采集的数据保持缺失，重新启用不补名额。

公开仓库只保留代码、合成测试和本文。真实任务样本及部署核验留在本机。
