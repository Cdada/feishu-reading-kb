# 过程文件保存与清理预览：阶段五

新整理输入快照中，已有卡片／主题正文只在 existing_files 保存一次；相同的全文与摘录只存一份。读取时在本机恢复完整输入，并核验文本和整体输入哈希。模型收到的输入、引文和独立复核要求均不改变。旧输入继续可读；已写入的历史文件不改写。空上下文的小文件可能增加少量格式标记，因此不承诺所有任务都节省空间。

保留原件、确认可用的 MinerU 原始 JSON/Markdown/图片、规范化正文、页码与表格映射、导读、笔记、卡片、主题、关联及其发布清单。当前请求和模型回执、输入证据、未完成任务、结果不明的尝试及已有清单引用的文件都保留。阶段三接续说明继续按稳定编号更新同一文档，解决后保留精简结论和人工备注；本阶段不新增逐次报告副本。

## 按需查看

使用已部署版本的 Python 入口：

    python retention_preview.py --daily-root <本项目运行目录>/conversion-work/daily-service

只输出 JSON 到标准输出，不创建报告或数据库，不调用飞书、模型或转换服务。需要保存时覆盖同一份本机报告，不能上传公开仓库。目录按已部署规则指定，不能扫描全盘或正式知识库。

清单包含材料标识、状态、相对位置、文件数、逻辑字节数、最近修改时间、保留原因和回退依赖。逻辑大小不是可释放磁盘空间，APFS 压缩／克隆会造成差异。读取失败、符号链接或条目上限会明确标记检查不完整。默认最多检查 100,000 个文件及目录条目，优先模型、整理和解析成果；大量请求回执最后统计。需要更完整清单时可显式增加 --max-entries（最多 500,000），依然只读，不把截断统计当成完整结果。未知文件、用户原件、成果库、模型和共享缓存不列入候选范围。

整理快照、解析成果及请求回执目前仍有不可变哈希和恢复依赖，因此清单直接标为保留；不能只凭“任务已完成”就删除。唯一可能列为人工审核候选的是本服务启动器的原子状态写入临时残留：必须已有更新的正式状态文件、服务停止、没有未完结／待排查任务或结果不明的调用，且距任务完成和文件修改均至少七天。这七天仍只是建议，未启用删除规则。

入口没有删除选项。候选数为零是正常结果，不能把所有中间文件都当成垃圾。实际删除须另行确认具体规则或清单；本阶段没有清理历史内容、恢复定时清理、迁移资料或改动备份。未经验证的引用关系继续保留，清理失败也不改变归档完成状态。

## 版本与恢复

输入文件的本地保存格式为 reading-input-storage/v1，始终自包含，不回读可能已改变的知识库来重建旧输入。独立请求、模型回执与发布计划保持现有格式。旧快照与现有未完成任务可直接继续。

阶段五之前的程序不能读取新压缩表示。需要回退时，先用阶段五冻结版本完成或核查使用新格式的未完成整理任务，再切换旧程序；不能覆盖数据库、改输入文件或重置模型计数来绕过检查。阶段五版本可继续使用原卡片和旧快照，因此无需批量迁移历史任务。

测试使用合成正文，核对无损还原、相同输入哈希、损坏拒绝、旧快照、完整整理与独立复核、暂停及结果不明保护、符号链接和只读清单。未开展真实知识库质量评测。
