# 飞书知识库日常入口

用户和本机 AI 共用已安装启动器；不要自行启动旧的 N6/N7/N8 验收脚本。

本机入口：`{{LAUNCHER}}`；Python：`{{PYTHON}}`。

- 查看状态：运行该入口，参数 `status --json`。只读本地记录，不产生飞书或模型调用。
- 启动：用户要求启动时，先查看状态；已运行就报告状态，否则运行 `start --json`。启动器会检查已批准的日常规则。无需对其范围内每份材料另写执行单。
- 停止：运行 `stop --json`，随后查看状态。`stop_requested` 表示已请求停止，只有 `running: false` 才表示进程已退出。

如果返回 `not_activated`，说明启动器已安装但日常规则尚未启用。告知用户需要完成一次集中启用；不要自行修改批准标记、增加正文额度、抹除失败记录或重置计数。

状态解释以三类信息为主：最近入库的一篇；仍需回复对应 PDF 或其他后续操作的材料；需要补传的材料。保留“已入库但通知待补”的区别。用户可以连续发多份文件，重型处理仍逐份执行。

Mac 重启后手动启动。当前支持单 Markdown、带内嵌图片的 Bear Markdown 和 Safari 网页归档；原图保留，未识读图片会标明，缺图先选择。知识库入库仍须用户直接回复对应 PDF 确认。

调用启动器不需要读取历史对话、凭据或真实原件。排查异常时先读本地状态和相关记录；跨出日常运行规则的新真实调用仍须用户明确授权。旧 iCloud/MinerU 转换流程继续使用原 `kb-ingestion-workflow` Skill。
